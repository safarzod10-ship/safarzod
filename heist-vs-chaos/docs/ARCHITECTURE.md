# Архитектура

```
 Kick chat / Kicks ──webhook (RSA-подпись)──▶ Caddy (HTTPS) ──▶ Fastify ──▶ KickIntegration ──▶ GameRuntime ──▶ SQLite
                                                                  │                                 │
 Телефон владельца ──HTTPS + Bearer token──▶ /api/admin/*  ───────┘                                 │ state
                                                                                                    ▼
 Chromium (Xvfb :99) ◀── WebSocket /ws?broadcast=1 ◀───────────────────────── полное публичное состояние
      │ звук → PulseAudio null-sink
      ▼
 FFmpeg x11grab + pulse ──H.264 CBR / AAC──▶ RTMPS Kick ingest
```

## Сервер (`src/server`)
- **runtime.ts** — авторитетный автомат состояний `intro → vote → resolve → (vote … | defeat | levelComplete) → campaignComplete`. Тик каждые 200 мс. Браузер ничего не решает: он только показывает состояние.
- **Транзакции и идемпотентность.** Закрытие голосования пишет строку `resolutions(vote_id PK)` и новое состояние в одной транзакции. Вмешательство пишется в `interventions(event_id UNIQUE)` и применяется в той же транзакции, что и изменение состояния. Webhook сначала записывает `processed_events(event_id PK)` и выполняет действие в той же транзакции.
- **Перезапуск.** Состояние хранится в виде JSON и восстанавливается при старте. Если процесс упал во время голосования, голоса восстанавливаются из таблицы `votes`, а таймер продлевается минимум на 10 с. Если упал во время анимации, результат уже записан и повторно не применяется.
- **Время.** Дедлайны хранятся в серверном времени. Скачки системных часов (NTP) обнаруживаются сравнением с монотонными часами и компенсируются. Пауза владельца сдвигает все дедлайны.
- **kick/kick.ts** — токен приложения (client_credentials), проверка канала по slug, подписки `chat.message.sent`, `kicks.gifted`, `livestream.status.updated`, перепроверка подписок каждые 5 минут, экспоненциальная задержка при ошибках (до 15 минут), проверка подписи по публичному ключу Kick с повторным запросом ключа при ротации, отсечение чужого канала, слишком старых событий и повторов.
- **broadcast/supervisor.ts** — запуск и наблюдение за Xvfb, PulseAudio, Chromium и FFmpeg. При сбое повтор через 5, 15, 30, 60, 120, 300 с. После 6 сбоев за 30 минут супервизор останавливается и пишет причину (бесконечного цикла нет). Сторожевые проверки: нет прогресса кодера 20 с; страница игры отключена 45 с; кодер медленнее реального времени 60 с — тогда профиль качества понижается. Учёт эфирного времени сохраняется в базе, поэтому лимит 5 часов не обнуляется при перезапуске.
- **secrets.ts** — ключ трансляции и ключи Kick хранятся в базе в зашифрованном виде (AES-256-GCM, ключ `SECRET_KEY` из `.env`). Функция `scrub` удаляет известные секреты, Bearer-токены и ключи из RTMP-URL из всех логов и из журнала ошибок в пульте.
- **app.ts** — Fastify. Лимиты тела запроса: 64 КБ для API и 256 КБ для webhook. Zod-валидация. CSP и другие заголовки безопасности. Блокировка IP после 8 неверных токенов. До 300 WebSocket-клиентов, ping/pong, отключение мёртвых соединений.

## Клиент (`src/client`)
- **game/** — Phaser 3 в режиме Canvas: на сервере без GPU это дешевле программного WebGL. Все спрайты рисуются кодом при загрузке: Canvas2D-градиенты, бумажные тени, «стежки» плюшевого робота. Фон каждой комнаты рисуется один раз в отдельную текстуру. Движутся только персонажи, лучи, конусы камер и частицы.
- **roomview.ts** — для каждого испытания строит подвижные объекты по подсказкам и состоянию и проигрывает физическое последствие выбранного варианта.
- **hud.ts** — DOM поверх холста. Крупный текст, читаемый на телефоне, обновляется 8 раз в секунду с проверкой изменений.
- **audio.ts** — WebAudio: шины music/sfx/voice → master → лимитер. Голос и сирены приглушают музыку. Одна реплика не повторяется чаще раза в 3 минуты.
- **panel/** — пульт владельца на простом TypeScript без фреймворка.

## Данные уровней (`src/shared/levels`)
`templates.ts` описывает 15 механик: вход, лазеры, камера, охранник, нажимные плиты, щиток, ключ-карта, дверь, кот, сувенирный магазин, витрина, погоня, прожектор и две комбинации. `campaign.ts` собирает из них 30 уникальных уровней. `validate.ts` полным перебором всех достижимых состояний проверяет каждый уровень: есть путь без урона; в любом состоянии есть безопасный ход; есть реальный выбор; подсказка задана; фазы идут по порядку; витрина ровно одна. Также проверяется уникальность названий, экспонатов и планировок.
