# Известные ограничения (честно)

1. **Реальный эфир на Kick ещё не проверен.** Конвейер вещания проверен с отправкой на локальный RTMP-приёмник: принятый поток содержит видео 720p30 H.264 и стереозвук AAC. Отправку в Kick, приём эфира на стороне Kick и чат через webhook можно проверить только после того, как будут получены ключ трансляции, ключи приложения Kick и сервер.
2. **Производительность измерена не на вашем VPS**, а в облачной среде, ограниченной 2 ядрами. На вашем сервере запустите `Encoder test`.
3. **Подарки (Kicks).** Схема события `kicks.gifted` взята из документации; полный список типов подарков Kick не опубликован. Эффекты подарков по умолчанию выключены. Возвраты платформа не предоставляет.
4. **Выплаты в Таджикистан** не подтверждены: Kick платит через Stripe. Статус KICK Streamer (5 часов эфира) назначает Kick, через API он не виден.
5. **Пакет образа** в приватном репозитории тоже приватный: нужен один шаг (сделать пакет публичным или выполнить `docker login`), см. SERVER.md.
6. **Голос робота** синтетический (espeak-ng) — намеренно роботизированный. Живую озвучку можно подключить своими файлами.
7. **Зрители на сайте** слышат звук только после нажатия «Tap for sound» (политика браузеров). На эфир это не влияет.
8. **Chromium в контейнере** запускается с `--no-sandbox`: он открывает только локальную страницу игры, а изоляцию даёт контейнер.
9. Предупреждения `npm audit` касаются только инструментов разработки (vite/vitest → picomatch). В рабочих зависимостях уязвимостей нет.
10. **Ключ трансляции передаётся FFmpeg в командной строке**: так FFmpeg работает с RTMP. В логах ключ вырезается, но root на сервере может увидеть его через `ps`. Сервер должен использоваться только вами. При необходимости смонтируйте `/proc` с `hidepid=2`.
11. Повторный запуск установщика перезаписывает `compose.yaml` и `Caddyfile` эталонными версиями. Свои настройки сохраняйте в `.env`.
