# Сервер и вещание

## Требования
Debian 12 / Ubuntu 22.04+, x86_64, от 2 vCPU, от 2 ГБ RAM (рекомендуется 4 ГБ), 4+ ГБ свободного диска. Входящие порты 80 и 443 нужны для HTTPS: Kick шлёт webhook только на публичный адрес. GPU не нужен.

## Установка
В веб-консоли хостинга под root:
```bash
command -v docker || curl -fsSL https://get.docker.com | sh; docker run --rm ghcr.io/safarzod10-ship/heist-vs-chaos:1.0.4 install | bash
```
Что делает установщик (`deploy/install.sh`; его можно запускать повторно):
1. Показывает ОС, CPU, RAM и диск. Останавливается, если свободно меньше 4 ГБ.
2. Ставит Docker официальным скриптом, если его нет. SSH, firewall и чужие контейнеры не трогает и выводит их список.
3. Создаёт `/opt/heist-vs-chaos/{data,.env,compose.yaml,Caddyfile}`. Файл `.env` (права 600) создаётся только один раз: секреты генерируются случайно и остаются на сервере.
4. Адрес сайта по умолчанию — `<ip-с-дефисами>.sslip.io`. Это бесплатное DNS-имя для IP, по нему Caddy получает сертификат Let's Encrypt. Свой домен задаётся так: `SITE_ADDRESS=game.example.com` перед командой.
5. Проверяет, что порты 80/443 свободны. Если они заняты чужой программой, установщик ничего не меняет и выходит.
6. Перед обновлением делает резервную копию базы и запоминает прежнюю версию для отката.
7. Запускает стек, ждёт `/healthz` и печатает: адрес игры, **приватную ссылку на пульт** (`/panel/#t=…`) и адрес webhook.

Сервис работает в контейнере от непривилегированного пользователя `heist` (uid 10001). Порт игры 8080 слушается только на `127.0.0.1`, снаружи доступен только Caddy.

## Сервер, где уже работает Caddy другого проекта
Если порты 80/443 занимает Caddy-контейнер другого проекта (на вашем сервере это `zuba-ruba-caddy-1`), установщик не трогает порты и не перезапускает чужой проект. Вместо этого он:
1. подключает игру к Docker-сети этого Caddy;
2. добавляет в его Caddyfile один блок между метками `# >>> heist-vs-chaos >>>` и `# <<< heist-vs-chaos <<<` (рядом сохраняется копия `Caddyfile.bak-hvc-…`);
3. проверяет конфиг (`caddy validate`) и плавно применяет его (`caddy reload`, без остановки). Если Caddy отклонит конфиг, исходный файл возвращается.

Если Caddyfile встроен в образ другого проекта (так у zuba-ruba), файлы не меняются вовсе. Маршрут игры добавляется через локальный admin API этого Caddy (`127.0.0.1:2019` внутри его контейнера). Таймер systemd `hvc-caddy-route.timer` раз в минуту проверяет маршрут и возвращает его после перезапуска или обновления того проекта. Ручная проверка: `hvc caddy-route`.

Адрес игры в этом режиме: `hvc.<ip-с-дефисами>.sslip.io`, чтобы не пересекаться с сайтом другого проекта. Если другой проект перезапишет свой Caddyfile, например при своём обновлении, запустите установщик ещё раз: блок добавится заново.

## Если образ не скачивается
Пакет `ghcr.io/safarzod10-ship/heist-vs-chaos` создаёт GitHub Actions; на 18.11.2026 он скачивается без входа. Если доступ будет закрыт, есть два способа:
- GitHub → ваш профиль → Packages → heist-vs-chaos → Package settings → Change visibility → Public. В образе нет секретов, только код игры.
- Или на сервере: `docker login ghcr.io -u safarzod10-ship`, в качестве пароля — токен GitHub с правом `read:packages`.

## Вещание
Пульт → Stream → Stream settings:
- **Stream URL** — из Kick Creator Dashboard, например `rtmps://fa723fc1b171.global-contribute.live-video.net:443/app`.
- **Stream key** — оттуда же. Хранится в зашифрованном виде и никогда не показывается и не пишется в лог.
- **Mode**: `Limited` — эфир прекращается, когда суммарное время эфира достигнет лимита (по умолчанию 5 ч). Счётчик хранится в базе и переживает перезапуски. `24/7` — без лимита.
- **Target**: `Encoder test` гоняет весь конвейер без отправки в Kick. Так можно измерить скорость кодирования на вашем сервере.

Профили (Kick: H.264 main, CBR, ключевой кадр раз в 2 с, AAC 48 кГц стерео):

| Профиль | Разрешение | FPS | Видео | x264 |
|---|---|---|---|---|
| hd30 | 1280×720 | 30 | 3000 kbps | veryfast |
| hd24 | 1280×720 | 24 | 2500 kbps | superfast |
| sd30 | 960×540 | 30 | 2000 kbps | veryfast |
| sd24 | 854×480 | 24 | 1500 kbps | superfast |

Включённый «auto» понижает профиль, если кодер 60 секунд подряд не успевает за реальным временем (speed < 0.95). Приоритет — стабильность, затем разрешение и FPS.

**Замер (облачная среда разработки, процесс ограничен 2 ядрами Xeon 2.1 ГГц):** hd30 — 30 fps, speed 1.00x, около 3,2 Мбит/с, суммарно около 60% одного ядра (ffmpeg ~30%, chromium ~30%), ОЗУ всего конвейера около 600 МБ. На вашем VPS цифры нужно подтвердить режимом *Encoder test*.

Важно: то, что FFmpeg отправляет кадры, ещё не означает, что Kick принял эфир. В пульте есть отдельная строка `Kick sees live`: Kick API отвечает, идёт ли эфир. Её надо проверять отдельно.
