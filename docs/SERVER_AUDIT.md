# Аудит рабочей среды (2026-10-31)

## ⚠ Главное: фактическая среда ≠ описанный VPS

Этап 1 выполнялся **не на вашем VPS**, а в облачном контейнере Claude Code
(сессия запущена из GitHub-репозитория `safarzod10-ship/safarzod`). Доступа к VPS
(Debian 12, 2 vCPU, 3.8 ГБ RAM, Cirrus GD5446) из этой сессии нет.

Следствия:
* Всё, что установлено вне репозитория (`/opt/*`, `~/.local/share/godot`, Android SDK),
  **исчезнет** вместе с контейнером. Сохраняется только то, что закоммичено в Git.
* Для VPS подготовлен воспроизводимый установщик: `tools/setup/install_toolchain.sh`
  (те же версии, проверка контрольных сумм) и `tools/setup/create_swap.sh`.

## Swap — оценка

* **Контейнер (15 ГиБ RAM):** не нужен. Пиковое потребление за все операции этапа 1 —
  **0.87 ГБ** (первый импорт Godot). Swap не создавался.
* **Ваш VPS (3.8 ГБ RAM):** рекомендуется **4 ГиБ swap-файл**. Blender с крупными
  сценами города, импорт десятков GLB и Gradle-сборка (если понадобится) превысят 3.8 ГБ.
  Скрипт `tools/setup/create_swap.sh`: не трогает существующий swap, проверяет место,
  `chmod 600`, запись в `/etc/fstab` (постоянное подключение), `vm.swappiness=10`.

## Графика без GPU

* Godot `--headless` использует фиктивный рендерер: сцены исполняются, но не рисуются.
* Для визуальной проверки установлен **Mesa lavapipe** (программный Vulkan) и использован
  Xvfb: рендерер Mobile реально рисует кадры на CPU (`llvmpipe (LLVM 20.1.2, 256 bits)`).
  Это подтверждает корректность сцен и материалов, но **ничего не говорит о
  производительности на телефоне** (FPS 3–16 на CPU).
* Android-эмулятор запустить нельзя: нет `/dev/kvm`.
