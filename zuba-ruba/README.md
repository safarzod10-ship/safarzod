# ZUBA RUBA

Telegram Mini App для бота [@zuba_ruba_bot](https://t.me/zuba_ruba_bot). Пользователи выполняют рекламные задания платформы Flyer, открывают кейсы, приглашают друзей и следят за начислениями. Все начисления считаются на сервере, у каждой операции с балансом есть уникальный ключ и запись в журнале.

## Установка

Нужен сервер на Ubuntu или Debian с публичным IP-адресом, открытыми портами 80 и 443 и доменом, A-запись которого указывает на сервер.

```bash
curl -fsSL https://raw.githubusercontent.com/safarzod10-ship/safarzod/claude/zuba-ruba-mini-app-83vt56/zuba-ruba/setup.sh | sudo bash
```

Чтобы сначала прочитать скрипт:

```bash
curl -fsSLo setup.sh https://raw.githubusercontent.com/safarzod10-ship/safarzod/claude/zuba-ruba-mini-app-83vt56/zuba-ruba/setup.sh
less setup.sh
sudo bash setup.sh
```

Что делает установщик:

1. Проверяет ОС, архитектуру, память и свободное место.
2. Проверяет git, curl, openssl, Docker и Docker Compose. Если чего-то нет, предлагает установить Docker из официального репозитория `download.docker.com`.
3. Скачивает проект в `/opt/zuba-ruba`. Каталог приложения — `/opt/zuba-ruba/zuba-ruba`.
4. Запрашивает токен бота и проверяет его методом `getMe`. Username бота берётся из ответа, вводить его отдельно не нужно.
5. Запрашивает Telegram ID администратора, ключ Flyer (проверяется методом Flyer `/get_me`), домен (проверяется DNS) и e-mail для Let's Encrypt.
6. Генерирует пароль PostgreSQL и секрет вебхука Flyer и записывает `.env` с правами `600`.
7. Собирает образы и запускает контейнеры. Миграции применяет сервис `migrate`.
8. Ждёт готовности API, затем проверяет `https://<домен>/health` и главную страницу.
9. Выводит адрес приложения и шаги подключения к BotFather и Flyer.

Повторный запуск обновляет код до последней версии ветки. Перед обновлением снимается резервная копия базы. Существующий `.env` не перезаписывается без подтверждения, а пароль базы и секрет вебхука никогда не генерируются заново. Тома с данными не удаляются.

### Подключение к Telegram

1. В @BotFather: `/mybots` → бот → **Bot Settings** → **Configure Mini App** → **Enable Mini App**, адрес `https://<домен>/`.
2. Кнопку меню «Открыть» и команду `/start` бот настраивает при запуске сам (`setChatMenuButton`, `setMyCommands`).
3. В @FlyerServiceBot укажите адрес вебхука `https://<домен>/flyer/webhook/<FLYER_WEBHOOK_SECRET>`. Установщик выводит его в конце.

### Панель управления

Панель находится внутри Mini App: **Профиль → Панель управления** (маршрут `https://<домен>/#/admin`). Строку видят только Telegram ID из `ADMIN_IDS`. Каждый маршрут `/api/admin/*` проверяет права на сервере, поэтому скрытая кнопка не даёт доступа. Открыть панель можно только из Telegram, потому что запросы подписываются `initData`.

## Возможности

- **Презентация при первом запуске:** три экрана. Факт прохождения хранится на сервере.
- **Главная:** общий, доступный и ожидающий баланс, сумма на выводе, открытые и готовые кейсы, последние операции, полная история с постраничной загрузкой, уведомления.
- **Задания:** список из Flyer `/get_tasks` с фильтрами «Все / Каналы / Боты / Бусты». Проверка через `/check_task` выполняется только на сервере. Каждая проверка пишется в журнал. Один `signature` может дать только одну награду: это гарантируют уникальные ограничения в базе и блокировка строки.
- **Кейсы:** после подтверждённого задания создаётся кейс, сервер выбирает приз по опубликованной таблице шансов. В приложении кейс открывается рулеткой: карточки со звездой Telegram и суммой едут слева направо и останавливаются на выигрыше под указателем. Повторное открытие возвращает тот же результат.
- **Удержание подписки** (по умолчанию 30 ч): награда остаётся в ожидании, пока не истечёт срок и Flyer не вернёт статус `complete`. Статус `abort` или `incomplete` отменяет награду. Задания, по которым Flyer слишком долго не подтверждает оплату или которые сняли с размещения, уходят на ручную проверку администратору.
- **Бусты:** первое начисление выдаётся после подтверждения Flyer. Повторные проверки идут через 48 ч, затем каждые 24 ч, и у каждого буста ведётся своя история периодов. Повторные начисления по умолчанию выключены (см. ограничения).
- **Реферальная программа:** за каждые три подтверждённых и открытых кейса приглашённого друга пригласивший получает подарочный кейс. Не учитываются ожидающие и отменённые задания, реферальные кейсы, самоприглашения, уже зарегистрированные пользователи и аккаунты с отметкой «подозрительный». Есть дневной лимит.
- **Уведомления в боте:** очередь в PostgreSQL. Дубли исключены ключом `dedup_key`. При временных ошибках и `RetryAfter` делаются повторные попытки, история доставки сохраняется.
- **Вывод подарками:** выбор конкретного подарка Telegram (анимации подарков проигрываются с частотой 30 кадров в секунду), резервирование цены, одобрение администратором или автоотправка, отправка через `sendGift`, возврат звёзд при отказе.
- **Администрирование:** обзор, поиск пользователей, карточка с балансом, операциями, рефералами, заданиями, бустами и заявками, блокировка, отметка «подозрительный», корректировки баланса с обязательной причиной. Также статистика заданий и ошибок Flyer, ручное решение спорных заданий, финансы и экономика, настройки, рассылки (текст, изображение, кнопки, предпросмотр, подтверждение, статистика доставки) и журнал действий.
- **Экономика:** валовый и подтверждённый доход, доход по ценам Flyer, расходы на награды и реферальные кейсы, ожидаемые начисления, неоткрытые кейсы, оценка комиссий вывода из Flyer, обязательства перед пользователями и чистая прибыль. Если ожидаемые расходы превышают подтверждённый доход, показывается предупреждение. Все тарифы редактируются в настройках и не считаются подтверждёнными тарифами Flyer.
- **Режим обслуживания и отключение функций** без перезапуска.

## Архитектура

| Компонент | Технологии |
|---|---|
| Mini App и панель управления | React 18, TypeScript, Vite, официальный `telegram-web-app.js`, CSS-токены (светлая и тёмная тема) |
| API | FastAPI, SQLAlchemy 2 (async), PostgreSQL 16, Redis 7 (rate limiting) |
| Бот и фоновые задачи | aiogram 3 (long polling) и процесс `worker`: перепроверка удержаний и бустов, очередь уведомлений, рассылки |
| Миграции | Alembic, сервис `migrate` запускается перед API и worker |
| Инфраструктура | Docker Compose, Caddy (автоматический HTTPS), ежедневный `pg_dump` в `backups/`, health checks, JSON-логи |

Суммы хранятся целыми числами: звёзды в тысячных долях (`milli`), рубли в копейках. Баланс пользователя меняется только в транзакции с блокировкой строки пользователя (`SELECT … FOR UPDATE`). Сверку кэшированного баланса с журналом операций выполняет `ledger.recompute`, она проверяется в тестах.

Подробный контракт API описан в [`docs/api.md`](docs/api.md).

### Безопасность

- Подпись `initData` (HMAC-SHA256 с ключом `WebAppData`) и срок `auth_date` проверяются на каждом запросе.
- Права администратора проверяются на сервере для каждого маршрута `/api/admin/*`.
- Rate limiting в Redis: общий лимит, лимит на проверки заданий, открытие кейсов и вывод.
- Заголовок `Idempotency-Key` обязателен для вывода и корректировок, ключи идемпотентности хранятся у операций.
- CORS разрешён только для домена приложения. Документация OpenAPI отключена.
- PostgreSQL и Redis не публикуются наружу. Секреты хранятся только в `.env` на сервере.
- Вебхук Flyer защищён секретом в пути. Событие `abort` не меняет баланс напрямую, а запускает внеочередную перепроверку через `/check_task`.

## Обслуживание

Обновление до последней версии (настройки берутся из сохранённого `.env`, вопросов нет):

```bash
curl -fsSL https://raw.githubusercontent.com/safarzod10-ship/safarzod/claude/zuba-ruba-mini-app-83vt56/zuba-ruba/setup.sh | sudo bash
```

Обновление с полным удалением базы данных (перед удалением снимается резервная копия в `backups/`):

```bash
curl -fsSL https://raw.githubusercontent.com/safarzod10-ship/safarzod/claude/zuba-ruba-mini-app-83vt56/zuba-ruba/setup.sh | sudo ZR_RESET_DB=1 bash
```

Сменить токен, администратора, ключ Flyer или домен: передайте новые значения в `ZR_BOT_TOKEN`, `ZR_ADMIN_IDS`, `ZR_FLYER_API_KEY`, `ZR_DOMAIN`.

```bash
cd /opt/zuba-ruba/zuba-ruba
docker compose ps
docker compose logs -f api worker
docker compose exec -T backup /bin/sh /backup.sh once
```

Восстановление из резервной копии:

```bash
docker compose stop api worker
docker compose exec -T postgres pg_restore -U zuba -d zuba --clean --if-exists < backups/zuba-YYYYMMDD-HHMMSS.dump
docker compose start api worker
```

## Разработка и тесты

```bash
# backend: нужны PostgreSQL и Redis
cd backend
pip install -r requirements-dev.txt
TEST_DATABASE_URL=postgresql+asyncpg://user:pass@localhost/zuba_pytest TEST_REDIS_URL=redis://localhost:6379/15 python -m pytest

# frontend
cd frontend
npm ci
npm run build
npm test
npm run e2e

# установщик целиком на локальном Docker (Telegram и Flyer подменяются)
bash tests/installer/run.sh
```

Backend-тесты используют настоящие PostgreSQL и Redis, а Flyer подменяется на уровне HTTP-транспорта. Они покрывают:

- регистрацию, повторный вход и онбординг;
- подпись `initData`;
- получение и фильтрацию заданий;
- проверку, повторную и параллельную проверку одного задания;
- кейсы и параллельное открытие одного кейса;
- удержание, подтверждение и отмену, ручную проверку;
- реферальные кейсы и исключения из реферальной программы;
- бусты и повторные периоды;
- вывод с параллельными заявками, отказом и возвратом;
- права администратора, настройки и журнал;
- корректировки, очередь уведомлений с повторными попытками, рассылки;
- вебхук Flyer, ошибки Flyer, перезапуск соединений, режим обслуживания и блокировку.

E2E-тесты Playwright снимают основные экраны при ширине 320, 360, 390 и 430 px в светлой и тёмной теме и проверяют отсутствие горизонтальной прокрутки.

## Ограничения внешних API

- **Flyer.** Документированы методы `/get_tasks`, `/check_task`, `/get_completed_tasks`, `/check` и `/get_me`, а также вебхук с событиями `test`, `sub_completed` и `new_status` (только `abort`). Поле `price` задания указано в рублях. Статусы `waiting` и `abort` возвращаются только для каналов в режиме «с проверкой».
- **Бусты во Flyer** — только тип задания `give boost`. В документации нет данных о посуточной оплате бустов и нет метода, подтверждающего оплату отдельного периода. Поэтому повторные начисления за бусты выключены (`boost_recurring_enabled = false`). Если их включить, начисление за период создаётся только при ответе `complete` на очередной `/check_task`, а не по прошествии времени.
- **Сроки и комиссии Flyer.** Документация не описывает сроки удержания оплаты, размер комиссии вывода и лимиты запросов. Значения в настройках («Комиссия вывода Flyer $3» и другие) — расчётные параметры владельца.
- **Подписи вебхуков Flyer** не документированы. Поэтому вебхук защищён только секретом в URL и используется лишь как сигнал к перепроверке.
- **Telegram Bot API** не позволяет переводить Stars на баланс пользователя. Единственный технический способ передать ценность в Stars — подарок `sendGift`, который оплачивается со Stars-баланса бота. Номиналы подарков ограничены списком `getAvailableGifts`, а Stars на балансе бота появляются только из платежей пользователей.
- **Профиль пользователя.** `photo_url` приходит в `initData`, только если пользователь разрешил показ фото.

## Выплаты и случайные награды

По решению владельца проекта вывод подарками и случайные призы в кейсах включены. Ответственность за соответствие правилам Telegram, Flyer и применимому праву лежит на владельце.

1. **Вывод подарками Telegram** (`withdrawals_enabled`, по умолчанию включён). Пользователь выбирает подарок номиналом 15, 25, 50 или 100 ⭐ (`withdraw_gift_stars`). Цена подарка резервируется с баланса, после одобрения бот отправляет подарок методом `sendGift`. Подарки оплачиваются со Stars-баланса бота, поэтому перед включением пополните его в панели управления. Если Telegram отказал, звёзды возвращаются пользователю. Автоотправка без одобрения (`withdraw_auto`) по умолчанию выключена.
2. **Случайный приз в кейсе** (`case_prizes`, по умолчанию `0.1:40,0.2:25,0.3:15,0.5:12,1:6,2:2`, средний приз 0,295 ⭐). Приз выбирает сервер криптографически стойким генератором при выдаче кейса, рулетка в приложении только показывает результат. Таблица шансов открыто опубликована в разделах «Кейсы» и «Правила». Участие бесплатное: пользователь ничего не платит за кейс.
3. **Повторные начисления за бусты** (`boost_recurring_enabled`) по-прежнему выключены, пока Flyer не подтвердит посуточную оплату бустов.
4. **Штраф в двойном размере награды при отписке** не реализован. Отписка в период удержания только отменяет ещё не подтверждённую награду.
